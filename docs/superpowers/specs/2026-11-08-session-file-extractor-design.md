# Session 文件提取页设计

日期：2026-11-08。基于当前 GPT Plus 工作台 v2.3.2；用户已确认使用 `.docx` 与 `.txt`，每份文件只有一个 Session。

## 目标

在工作台左侧增加独立的“Session 提取”页面。用户可以通过文件选择器或拖放单个 Word `.docx` / `.txt` 文件，从中提取与账号池一致的 Session JSON，并一键复制紧凑单行文本。

## 交互与格式

- 左侧导航新增“Session 提取”，不放入账号详情或充值流程。卡密及单个 / 批量充值的规格顺序调整为半价 Plus 在普通 Plus 前；规格 ID、资格校验和库存分配规则保持不变。
- 页面提供文件选择区与拖放区；一次处理一个文件，支持清除后重选。
- 从文本中识别现有 Session 对象结构：`user.email`、`accessToken`、`sessionToken` 和 `expires`。解析成功后按 JSON 紧凑序列化，呈现邮箱与只读文本框，复用账号池的“复制 Session”交互。
- 此功能只表示“已提取”，不把存在于文件中的令牌标成实时有效，也不调用 GPT 或兑换服务验证。
- 在文档文本中查找完整 JSON 对象，并要求对象含 `user.email`、非空 `accessToken`、非空 `sessionToken` 与 `expires`。未找到、格式损坏、超过 10 MiB 或发现多个匹配对象时显示明确错误，不尝试猜测或自动选择。

## 文件处理与隐私边界

- `.txt` 优先使用 UTF-8 / UTF-8 BOM 解码，必要时回退 GB18030。
- `.docx` 使用 Python 标准库读取 ZIP/XML 中的段落与表格文字，不增加第三方依赖；旧版二进制 `.doc` 不在本次范围内。
- 文件内容通过本机工作台的认证接口传入后端，并只在本机进程内存中解析；不写临时文件、数据库、日志、升级包或导出文件。关闭或清空页面后丢弃解析结果。
- 每次仅接收一个 `.docx` 或 `.txt` 文件，最大 10 MiB；服务端再次校验扩展名、大小与 ZIP/XML 结构。禁止在错误信息或请求日志中回显文件名、文件内容或 Session。

## 验证

使用合成凭据生成 TXT 和 DOCX 样本，覆盖有效单对象提取、Unicode 内容、表格内 JSON、无匹配对象、损坏 DOCX、非法 JSON、多对象歧义、超限文件、清空与重选。验证复制结果与账号池相同字段且为单行紧凑 JSON；检查本地数据库、日志和输出目录没有新增凭据或样本文件。运行 Python / JavaScript 回归并构建生产前端。升级后台时沿用现有安全交接，不能直接终止进程或丢弃内存 Session。

## 验收标准

1. `.docx` / `.txt` 可选择或拖入；单个有效 Session 显示并可复制。
2. 复制文本为账号池相同的紧凑 Session JSON，不引入额外包装对象。
3. 错误或歧义输入不会产出候选凭据。
4. 无持久化、日志泄漏或真实 Session 测试。
5. 侧栏页面可用，构建与回归通过，使用说明同步更新。
