# Session 直充与卡密详情设计

日期：2026-11-08。基于 v2.3.6 Partner API 工作台。

## 目标

让“Session 提取”页面能够直接使用提取出的 Session 和用户手动输入的 Plus / 半价 Plus 卡密完成一次充值，同时让本机操作者在卡密详情中查看和复制完整卡密。

## 设计

- Session 提取页保留单个 DOCX / TXT 文件解析结果，新增卡密输入、规格选择、预检和确认直充。
- 直充使用独立 `session_extract` 任务，不创建账号池账号；充值记录只保存邮箱、脱敏卡密、规格、预检摘要和结果。
- Session 只在后台内存中存在，用于一次 `preflight` 和 `redeem`。任务状态、列表、导出和日志不包含 Session。
- 未完成直充为恢复原交易，会将卡密和 Partner 交易 token 以当前 Windows 用户 DPAPI 加密暂存；终态时清空这些字段。列表、状态接口和导出只显示脱敏卡密。
- 直充使用固定 Partner API 八端点中的 `lookup`、`preview`、`preflight`、`redeem`、`result`、`result-by-code`，不新增上游 URL；提交仍只允许一次，结果不确定时只查询原交易。
- 直充卡密与库存卡密按摘要去重；已在卡密管理中的卡密不能绕过库存再直充。直充历史不自动加入账号池。
- 卡密列表和 `/api/inventory/state` 永远只返回脱敏值。用户点击“详情”后调用独立 `/api/inventory/card-detail`，后端在内存中解密并返回完整卡密；详情提供复制，关闭后前端丢弃明文。
- 卡密核对失败只保存固定错误代码和安全中文提示，区分授权、限流、网络、上游超时、响应格式和状态冲突；不会写入完整远端响应或卡密。
- 已确认使用的卡密遇到后续不一致结果仍保持“已使用”；“未使用”只有上游明确 `can_resubmit: true` 时才释放回库存。

## 验证

使用合成 Session 和合成 Provider 覆盖：详情接口单独解密、列表不泄露明文、核对授权失败不改变库存、未允许重提的未使用状态进入异常、直充成功归属、独立任务重复提交保护、直充不创建账号池且不持久化 Session。未使用真实 Session、真实卡密或真实 Partner API。
