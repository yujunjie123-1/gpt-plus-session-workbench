# Session 直充产品识别与 Partner 授权提示

## 背景

Session 提取页当前要求选择 Plus 或半价 Plus，并把选择值传入直充预检。卡密实际产品、套餐和金额由 Partner API 根据卡密决定，因此本地选择会拒绝 iOS、多倍率卡密和点数卡。当前 Windows 进程、用户和系统环境均未设置 `CDK_PARTNER_PASSWORD`；Partner 客户端在创建时会抛出授权配置错误，但卡密核对流程将其归为笼统的 `CHECK_FAILED`，界面无法指出原因。

## 目标行为

- Session 直充页面只要求 Session 和卡密，不显示或发送本地充值规格。
- 先执行已有卡密状态查询，再调用文档规定的 `preview`；只接受其 `data.product`、`data.plan` 和 `data.redemption_token`。产品与套餐按上游原值显示，不建立本地 SKU 映射，也不从卡密文本推断。
- 用户核对账号邮箱、上游产品/套餐和当前订阅信息后，沿用已有 `preflight`、明确确认、单次 `redeem`、原交易状态查询和邮箱归属流程。
- Session 直充记录保存上游 `product` 与 `plan` 供历史列表和导出展示；Session、完整卡密和 Partner 凭证继续按既有生命周期处理，不增加明文持久化。
- 普通账号池的 Plus / 半价 Plus 库存分配和精确资格校验保持不变。
- 账号已有套餐的本地 Plus 冲突检查只用于上游 `product: gpt`；其他产品只依赖 Partner 预检返回的阻断信息，避免将相同 `plan` 文本跨产品套用。
- 卡密状态核对将“未设置 `CDK_PARTNER_PASSWORD`”显示为可操作的配置错误。错误密码仍显示 Partner 授权失败；网络和上游错误继续保留各自分类，所有失败均不改变本地卡密状态。
- 使用说明记录 Windows 用户环境变量 GUI 配置和完全重启后台使配置生效的步骤。

## 实现边界

后端增加通用 Partner 预览资格解析，仅用于 Session 直充；现有 Plus 库存充值继续使用严格的 `plus_qualification`。直充预检依然使用固定文档端点和字段，不新增 API，不绕过卡密状态、Session 邮箱、账号阻断、凭证存在性或确认步骤。GPT Plus 的本地套餐冲突检查仍保留；其他产品按 Partner 上游的阻断字段判断。未知或格式异常的产品/套餐、缺少兑换凭证时，在 Session 预检前停止。

前端以原始上游产品和套餐构造确认文本、充值记录及导出文本；旧直充记录继续通过现有 Plus 规格标签显示。核对错误使用独立的配置缺失代码，不把异常文本或响应内容拼入 UI。

## 验证

- 用合成 `preview` 覆盖 GPT Plus、半价 Plus、iOS 5×、卡密 5×/20×/50×及点数类标识，确认各自原值显示且请求不包含 `sku`。
- 验证缺少产品/套餐/兑换凭证会停止，账号池 Plus 资格严格检查仍拒绝其他产品。
- 用合成 Provider 验证 `CDK_PARTNER_PASSWORD` 缺失与错误密码提示不同，并确认核对错误不修改本地卡密状态。
- 验证直充记录与 CSV 含上游产品/套餐、不含 Session、完整卡密和 Partner token。
- 运行相关 Python 测试和前端生产构建；不查询真实卡密、不调用真实兑换接口、不重启当前后台。

## 不在本次范围

不增加 iOS、倍率或点数卡库存 SKU，不为卡密类型建立推测性映射，不修改账号池充值规格，不自动提交或重试新的兑换，不验证用户截图中的真实卡密。
