# 充值结果收口与账号池 Session 复制

## 目标

修复已提交兑换在本地任务被停止后没有正确收口的问题，并让账号池每行的操作入口直接复制该账号的 Session。卡密和充值历史必须保留，只有用户主动删除卡密时才归档或移除。

## 行为设计

### 充值结果

- 上游明确返回成功且邮箱与目标账号一致时，任务进入“充值成功”，账号当前套餐标记为 Plus，写入成功历史，卡密标记为“已使用”并继续出现在卡密管理。
- 上游返回成功但邮箱不一致时，任务进入“待人工核实”，保留卡密占用状态，不自动把成功归属到当前账号。
- 任务详情提供“确认已到账到此账号”和“确认由其他邮箱使用”两个动作。
  - 确认到账：按成功结果收口当前账号和卡密。
  - 确认其他邮箱：卡密标记已使用，当前账号释放充值占用但不增加成功历史。
- 停止任务只停止本地执行，不撤回已经提交的远端兑换；之后仍可查询原任务或完成上述人工收口。

### 卡密管理

- 任何成功或人工确认成功的卡密都保留在列表，状态显示为“已使用”。
- 待人工核实的卡密显示为“占用中”，不可重新分配或删除。
- 只有用户手动删除已使用卡密时才归档并从默认列表隐藏，充值记录继续保留。

### 账号池操作

- 普通账号行右侧的“移入风控池”替换为“复制 Session”，调用现有只读 Session 查看接口并沿用紧凑单行 JSON 格式。
- 账号未获取、已失效或当前没有可复制 Session 时按钮禁用并说明原因。
- 勾选账号后出现的批量工具栏继续保留“移入风控池”，位置仍在“删除”左侧。
- 账号行已有的“一键复制”资料操作不变。

## 实现边界

- Session 仍只在后台内存中保存；本次不把 Session 写入数据库、日志或导出文件。
- 人工收口动作只允许作用于当前账号的待核实提交任务，并在后台再次校验任务状态，避免重复归属。
- 使用合成上游响应覆盖：明确成功、邮箱不匹配、人工确认到账、确认其他邮箱、卡密保留和重复收口保护；前端构建验证行级按钮位置。
