# Session 生命周期规则（当前 v2.4.1）

## 范围与现有标记

在 v2.2.3 上增量实现。账号是否使用过沿用现有 `has_successful_recharge`：账号成功标记、最近成功记录及按邮箱关联的成功任务历史。当前没有独立的已交付标记，本次不新增；一键复制资料不代表交付。当前套餐 Free / Plus 不作为从未使用的证据。

后台自动更新与“更新符合条件的 Session”仅操作普通池、无成功历史、无运行中的登录 / 充值任务、无充值处理中或待核实提交的账号。缺少 GPT 密码时提示补全。旧的用户明确发起的单账号获取、查看和复制入口保留；它们不会开启后台维护。新批量更新入口严格执行本次筛选范围。

## 状态与时间

账号池以 Asia/Shanghai 时区显示获取时间、Session 标注到期和可解析的 Access Token 到期。状态为未获取、可用（本地检查）、即将过期、已过期、已失效。明确拒绝时显示服务端已拒绝的时间；成功预检显示“兑换预检通过”的时间与来源，不宣称是 OpenAI 持续验证。未来日期和内存中存在值都不等于服务端实时接受凭证。

有效期判断检查邮箱、必要的 Access Token 和 Session Cookie、含时区的 Session expires。JWT 必须结构可解析、算法字段合法、exp 为有限数值，才读取其声明。此处不验证 JWT 签名，只把该声明当作保守上界；更新截止取 Session expires 与令牌声明的较早时间，绝不用于延长有效期或认定服务端有效。令牌为不透明值或无法解析时明确标为未知，不编造期限。

账号池 Session 以当前 Windows 用户 DPAPI 加密后保存到独立 SQLite 表，后台启动时仅恢复结构完整、邮箱匹配且本地时间检查通过的凭证；解密失败、邮箱不匹配或已过期的密文会被删除。数据库不会把 Session 放进前端快照、日志、导出或充值记录。充值成功、人工确认到账、服务端明确拒绝或删除账号时，只删除对应账号的 Session；其他账号不受影响。重启后没有恢复 Session 的账号显示未获取，即使白名单时间元数据仍在未来。历史期限已过可显示已过期，仍不会视为服务端实时验证通过。

## 调度与失败处理

“自动更新 Session”默认关闭，可持久化开关。启用后立即检查，此后后台每 30 秒检查，页面关闭也继续运行；电脑休眠 / 关机时不能运行。符合范围的账号在无 Session、明确失效、已到期、或者已知截止不足 10 分钟时排队。

“更新符合条件的 Session”由用户明确发起，强制更新该范围内的账号并重置本轮重试次数，便于修正资料后重新尝试。账号已有任务则跳过。任务与现有 Session 获取任务共用同一个并发限制，默认 5、可调 1–10；充值并发独立。

同一账号只允许一个任务。排队执行前及等待名额期间再次检查资格；通过账号池操作移入风控的排队维护任务可被跳过。后台巡检也会停止变成风控或具有成功历史的维护任务。关闭开关会取消由后台自动排队 / 执行的维护任务，不取消用户手动发起的更新任务。

网络 / 浏览器暂时失败后分别退避 1 分钟和 5 分钟，本轮最多 3 次，之后需要人工点击更新。重试计数和冷却时间不含凭证，可跨后台重启保留。账号密码错误、取码配置缺失、无法判断验证码、人机验证或超时等需要人工处理的情况停止自动重试，提供固定提示，不无限打开窗口。修正后可用原有手动获取入口完成交互，或点击批量更新开始新一轮。

## 充值前检查

每次预检先检查必要凭证及保守截止；缺失、失效、到期或即将过期时使用现有独立 Edge InPrivate 登录重新获取。兑换服务明确返回目标 Session 失效时清理旧的预检票据，最多重新登录并预检一次；普通 401 / 403、网络错误、服务权限错误不能据此判定 GPT Session 失效。

正式提交前再次比较本地有效期及预检所用的 Session 指纹；变化时重新预检。指纹仅留在内存票据，不提交供应商、不持久化。已经提交后仍遵守原交易查询与卡密锁规则，禁止因登录失效再发一次兑换。

这是一套及时更新与使用前验证机制，不是对“永远实时有效”的保证。没有稳定、独立的服务端验证接口时，不额外循环调用未确认的 GPT 内部接口，也不通过轮询真实卡密充当保活。

## 验证

tests/test_session_lifecycle.py 使用合成 Session、模拟时钟、模拟登录与模拟兑换服务，覆盖筛选、JWT 提前到期、未知时间、重启、后台巡检、去重、共享并发、有限退避、人工处理、排队资格改变、活跃任务停止、充值前刷新、明确拒绝与普通网络错误的区别。tests/test_inventory_browser.py 验证北京时间、状态、默认关闭、开关和新按钮；手机网关测试验证受配对保护的接口。

不使用真实卡密，不把真实账号凭据写入用例。具体结果见 output/v230-tests.json、output/v230-tests.log、output/v230-javascript-tests.json。部署前先检查空闲任务；沿用正常关闭和内存交接升级，不直接杀后台，不向升级文件写 Session。
