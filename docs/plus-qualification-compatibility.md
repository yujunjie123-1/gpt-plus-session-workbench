# Plus 卡密资格检查记录

日期：2026-11-09。当前版本为 v2.4.0；本记录保留历史兼容背景，并以 Partner API 规则为准。

## 当前 Partner API 检查规则

按 `cdk-partner-kit-v1` 当前文档，预览响应必须来自 `data` 且同时含有产品和套餐。账号池普通充值只接受 `product: gpt`，并要求套餐精确匹配库存规格：`plan: plus` 或 `plan: plus_half`。Session 提取直充不再指定库存规格，读取并展示上游返回的任意非空 `product`、`plan`，因此可覆盖 Partner API 支持的 iOS、倍率和点数类产品。两条路径都要求兑换凭证存在；缺产品、套餐或兑换凭证时均在发送账号 Session 预检前停止。资格判断只使用文档定义的 `product`、`plan` 和 `redemption_token`；未记录在该 Partner API 契约中的 `plan_type`、`token` 别名及响应外层字段不作为资格依据或凭证。

历史 v2.3.1 曾基于旧兑换组件处理外层令牌和通用 `token` 兼容。该历史路径不适用于当前 Partner API；请以本节固定契约和当前代码为准。

## 历史报错位置和确认的缺口

旧提示“首版仅接受明确的 Plus 卡密；上游未返回有效 Plus 兑换资格”来自卡密 `preview` 返回解析。此时尚未调用账号 `preflight`，也未调用 `redeem`。该提示把非 Plus、套餐缺失和令牌缺失混在一起，因此单凭提示不能判断这张实际卡密无效。

历史旧组件曾从 `data.redemption_token`、外层 `redemption_token`、`data.token`、外层 `token` 读取资格凭证；当前 Partner API 不再沿用这些未列入契约的别名，只接受 `data.redemption_token` 和 `data.preflight_token`。

## 本次修改

- Provider 仅解析 Partner API `data` 包络内的文档字段，不将响应外层或通用 `token` 合并为资格凭证。
- 账号池普通充值必须同时有 `product: gpt` 和明确的 `plan`，并精确匹配库存规格；Session 直充则要求产品和套餐均为非空文档字段，不建立本地 SKU 映射。两者都不根据额外字段、卡密前缀、库存分类或人工账号标签推断资格。
- 将“未返回卡密产品”“产品不是 GPT”“未返回卡密套餐”“套餐不是所选规格”“缺少兑换资格凭证”分开提示。远端任意内容、完整卡密和凭证不进入错误文本或持久化记录。
- 仍然先核验卡密状态，再核验账号，最后按原确认流程提交一次；提交结果未知仍只查询原交易。

完整 Python 回归 154 项中 146 项通过、8 项按原有显式条件跳过，无失败或错误；JavaScript 24 项通过；前端构建通过。电脑后台更新时的 3 个 Session 全部按原值恢复，库存、历史和设置保留。手机网关无需重启，配对及当前前端资源校验通过。

本次未调用真实卡密的 lookup、preview、preflight 或 redeem，未验证真实到账。实际卡密触发旧报错的具体字段仍需经授权只读查询确认，不能把已修复的兼容缺口当成这张卡密资格有效的证明。

## 使用

安全更新后台后刷新电脑或手机工作台。旧充值记录保留原提示，不会被改写为成功，也不会自动重试历史任务。重新发起充值仍需用户确认账号和卡密分配；确认后，预检通过会按原有流程实际兑换并消耗卡密。

若新版仍提示产品缺失、产品不是 GPT、套餐缺失 / 不符或缺少资格凭证，应按具体提示核实供应商返回，不应通过放宽产品校验继续充值。
