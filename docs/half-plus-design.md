# 半价 Plus 独立类型修复方案与实现记录

日期：2026-11-08。设计基于 v2.3.1；实现版本 v2.3.2。支持明确的半价 Plus，同时避免与普通 Plus 混淆。

## 已确认的事实

供应商公开充值页面脚本 `https://cdk.bar/assets/RechargeView-URHELJji.js` 的 ChatGPT 产品集合同时列出 `plus` 与 `plus_half`。当前本地 Provider 只接受 `plus`，库存与界面也只有普通 Plus，所以半价卡被拒绝。用户提供的旧版组件 ZIP 不包含半价标识；以已观察到的公开页面标识为兼容依据，不从卡密前缀推断资格。

没有查询真实卡密或提交真实 Session；具体半价卡的资格、账号限制和实际到账尚未验证。沿用现有 preview、preflight、redeem、lookup 接口及确认令牌流程，不猜测其他支付接口或绕过预检。

## 推荐改动

1. 新增独立 SKU `plus_half`，界面显示“半价 Plus”。普通 Plus 保留 `plus`。卡密导入、库存筛选、单个充值、批量充值、分配确认、进度、详情、历史及导出均保留区别。
2. 资格预检仅接受对应的明确套餐值：普通 Plus 必须为 `plus`，半价 Plus 必须为 `plus_half`；缺失、冲突、其他套餐或与选定库存规格不一致时停止，不提交兑换。两者购买的账号套餐均是 Plus，但卡密商品规格分别显示；已有 Plus / Pro 账号的阻止规则同样适用。
3. 增加未使用卡密的“修改规格”，用于纠正旧版错放到普通 Plus 分类的半价卡。仅允许未使用、未占用、无待核实提交且当前未核对的卡密修改；失败但尚未提交且已释放的卡密可以修改。原充值历史的 SKU 保留，不按新分类重写。
4. 不自动修改真实库存分类；不根据卡密前缀迁移；不自动重新发起旧任务；不改变 Pro 的仅库存管理状态。
5. 以合成账号和模拟供应商响应验证两类型成功、相互错配拒绝、并发分配不串库、禁止修改占用 / 使用 / 待核实卡密、历史保留、界面及导出名称。构建前端并更新使用说明，使用现有内存交接机制更新空闲后台，保留 Session 和手机配对。

## 方案比较

- 推荐：独立 SKU 和严格匹配，操作上多一个分类，但库存、确认及历史都能准确区分。
- 仅放宽资格函数同时接受两个值：改动少，但用户选择普通 Plus 时也可能消耗半价卡，不符合本次“不能混淆”的要求。
- 按卡密前缀自动改类：方便但没有可靠的服务端资格证据，不采用。

## 验收边界

原有未知提交锁、成功账号保护、风控池排除、Session 内存保存及更新规则继续生效。不消耗真实卡密完成本地测试，模拟成功不表示真实到账。当前无 Git 仓库，设计文档保存在维护目录中。

## v2.3.2 实现状态

- `workbench/products.py` 新增 `plus_half`，`workbench/provider.py` 精确要求套餐与选定 SKU 相同；`engine.py` 在给账号凭证前校验。若选中 Plus 但上游返回 `plus_half`（或反过来），只在本地查询卡密资格后停止，session preflight / redeem 均不调用。
- `workbench/inventory_store.py` 提供原规格乐观并发保护的修改入口。成功卡密或关联任务存在待核实提交、在核对中、已归档或库存状态非 unused 时禁止修改；已释放且未提交失败记录的卡密可改类。历史任务 SKU 不跟随库存 SKU 改动。
- 卡密管理支持五种独立标签、操作按钮、详情弹窗和新规格对话框；手机 Tailscale 路由允许该指定操作。充值选择、分配、进度、充值记录和 CSV 导出继续使用独立 SKU。
- 修改成功时写入非凭证的变更前 / 后 SKU 与时间，不持久化卡密、Session 或上游凭证。充值卡密全局去重，不可通过另一规格重复导入。
- 完整 Python / JS / 界面回归、后台 Session 交接、手机配对保留和发布包检查结果见交付说明所链接的 `output/v232-*.json` 报告。

## v2.3.3 展示顺序

- 半价 Plus 仍为独立 `plus_half` SKU；只调整产品声明与前端选项的展示顺序，使卡密管理及单个 / 批量充值中半价 Plus 排在普通 Plus 前。资格匹配、历史记录及库存绑定不变。
