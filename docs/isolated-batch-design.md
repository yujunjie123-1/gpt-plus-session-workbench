# 独立 InPrivate 与批量并发（v2.2.2 当前规则）

用户已要求接入前一版调查提出的独立资料目录方案，支持一次选择 5、10 个账号。保持既有一次确认、风控过滤、库存占用和未知结果不重复提交规则。

## 已选方案与替代方案

使用原生 Edge，每个登录尝试创建独立绝对资料路径，按账号内部 ID、随机实例 ID 分级。不同登录尝试也不复用浏览器目录。普通新窗口仍会共享 Cookie；WebView2 需要重做真实登录接入；受控 Playwright 登录此前有 400。因此本次采用原生 Edge 加独立资料目录。

本机 Edge 156 已用仅访问本地页面的探针验证：命令行加载助手有效；新目录默认没有 InPrivate 权限；仅改偏好文件不会可靠授权。初始化阶段使用后台 Edge 和浏览器自己的扩展配置 API，只给工作台自带助手启用 InPrivate，不改系统策略、不复制日常浏览器资料、不访问 GPT。初始化进程必须完全退出，才以没有调试参数的原生 Edge 启动实际 InPrivate 登录。策略拒绝或能力缺失时明确失败。

## 组件和数据流

1. 浏览器管理器复制白名单助手资源到工作台专用目录，使用公开固定扩展 key 确定助手 ID；不保存密码、验证码或 Session。仅从未登录的空白配置建立模板；工作台启动时在后台准备，按浏览器及助手版本失效更新。每个登录尝试复制到全新独立目录，不从已登录目录生成模板。
2. 引擎在内存创建账号、登录请求、实例和一次性启动口令的绑定。普通全局助手看不到这些独立任务。
3. 新 InPrivate 窗口先访问本地连接页，启动口令在 URL fragment 内。该目录自己的助手交换一次性口令，获得仅本实例有效的内存授权；随后同一个标签页自动转入登录页面。
4. jobs、凭据步骤和 Session 接收均在后端核对实例授权、任务随机 ID、邮箱和到期时间。其他实例的 token 不能读取或完成本任务。
5. 助手只操作有本任务标记的标签页，登录和验证码逻辑沿用已有实现。Session 核对完成后回到引擎，关闭本任务自己的浏览器并清理其临时资料目录，再按原流程预检、兑换和查询。
6. 停止、异常、超时同样撤销实例授权和清理本任务窗口；不会关闭日常 Edge 或前版保留的窗口。停止准备中的任务也会等待准备线程退出，不能遗留后来弹出的登录窗口。

## 调度与界面

Session 获取和充值分别控制并发，均为 1～10；Session 默认 5，充值默认 1，两者设置独立且重启保留。删除独立登录的全局串行锁，同一账号不允许重复任务。初始化、登录、验证码、预检、兑换和结果查询都占用对应任务的并发名额；单个错误不阻断其他账号。降低并发不取消已经开始的任务，只限制后续入场；暂停阻止新任务入场，不伪称能撤回已提交的远端兑换。

批量页说明每个任务使用独立窗口并在 Session 获取后关闭。侧栏显示独立登录已启用与当前连接实例数量，不再要求日常资料目录的全局助手在线。保留原有任务进度和失败提示。

## 验证与边界

覆盖 5/10 个任务并发、超限排队、不同任务交换口令与 token 拒绝、取消和迟到交接、初始化失败隔离、库存与账号策略、浏览器资料路径及 Cookie 隔离、实际本机升级和安装包持久化。网络、充值成功和拒付使用合成数据与模拟服务。隔离能力不能保证 OpenAI 一定接受某次登录，也不改变支付侧限制；真实充值成功仍以兑换服务返回并核对账号的结果为准。

本版保留升级时已有的内存 Session；账号、卡密、充值记录仍使用固定 SQLite。设计自检：无未定项；本次不更换兑换供应商、不增加 Pro 兑换能力、不复制日常浏览器资料。
